# 项目工作台（PMP）

个人用的项目管理工具，本地优先、离线可用。当前进度：**阶段 0–4 完成，另外做了重复任务和任务模板**。

## 日常使用（推荐）

双击项目根目录的 **`启动.cmd`**。它会：

1. 第一次运行时自动构建（之后直接跳过）
2. 起一个本地服务并打开浏览器 http://localhost:5180

两个注意：

- 那个黑色命令行窗口不要关，关掉服务就停了。
- 数据存在浏览器的本地存储里，绑定 `http://localhost:5180` 这个地址。所以请**一直用同一个浏览器、同一个地址**打开，别换端口或换浏览器，否则会看不到原来的数据。

想让开机自动启动：按 `Win+R` 输入 `shell:startup`，把 `启动.cmd` 的快捷方式丢进去。

## 打不开怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 浏览器显示「拒绝连接」/「无法访问此网站」 | 本地服务没在跑 | 双击 `启动.cmd` |
| 命令行提示端口已被占用 | 服务已经在运行 | 直接刷新浏览器即可 |
| 页面能开但数据是空的 | 换了浏览器或换了端口 | 用回原来那个浏览器的 `http://localhost:5180` |

> 服务只监听本机回环地址（IPv4 和 IPv6 都听），不会暴露到局域网。

## 开发

```bash
pnpm install
pnpm dev          # 开发模式，自动打开 http://localhost:5180
pnpm build        # 产出 dist/
pnpm build:site   # 产出 dist-site/（要部署到 GitHub Pages 的只读站点）
```

验证：

```bash
pnpm typecheck
pnpm build
node tools/smoke.mjs http://localhost:5181/            # 列表视图 / 详情 / 持久化
node tools/smoke-views.mjs http://localhost:5181/      # 看板拖拽 / 时间轴拖拽 / 依赖连线
node tools/smoke-reminders.mjs http://localhost:5181/  # 今日视图 / 提醒 / 设置
node tools/smoke-search.mjs http://localhost:5181/     # 全局搜索 / 筛选 / 保存视图
node tools/smoke-templates.mjs http://localhost:5180/  # 重复任务 / 模板 / 本地服务
node tools/smoke-site.mjs http://localhost:5182/       # 只读站点（vite preview --config vite.site.config.ts）
```

## 现在能做什么

- 侧边栏：收件箱 / 今天 / 即将到期 / 全部任务 / 按项目 / 归档，带未完成计数
- 列表视图：按状态分组，可折叠；显示状态、优先级、标签、截止时间；逾期标红
- 看板视图：四列按状态分组，卡片可拖拽改状态（鼠标和触屏都行）
- 时间轴视图：甘特条按日期铺开，支持周 / 两周 / 月三档缩放；**拖动色条改期，拖两端改工期**
- 任务依赖：在详情里添加前置任务，时间轴画出依赖连线；前置未完成就开始的会标成红色虚线冲突
- 今日视图：逾期 / 今天到期 / 进行中未排期 / 今天完成四块，带今日完成进度
- 提醒：按任务的截止日 + 提前量提醒，可设为准时 / 提前 1 小时 / 1 天 / 3 天 / 1 周
- 设置：提醒时刻、桌面通知开关、数据备份导出导入
- 全局搜索：⌘K / Ctrl+K 打开，搜任务标题和备注内容、项目、标签，↑↓ 选择回车打开
- 筛选与排序：关键字 / 状态 / 优先级 / 标签 / 截止条件，五种排序方式
- 保存视图：把「看哪儿 + 哪个视图 + 筛选 + 排序」存成侧边栏里的一个入口，点一下就还原
- 重复任务：每天 / 每个工作日 / 每周 / 每月。完成后自动生成下一次
- 任务模板：在任务详情里「存为模板」，之后在侧边栏「模板」区点一下就能建任务
- 任务详情抽屉：标题、状态、所属项目、优先级、起止日期、标签、Markdown 备注（带预览）
- 快速新增：输入框敲一句话回车即建任务
- 新建项目：名称 + 颜色
- 数据持久化：写在 IndexedDB，刷新不丢

## 交互约定

- 拖动色条改期，拖动两端改工期，松手才写数据（拖动过程中不写，避免日志被刷爆）
- 依赖是**手动模式**：只画连线和提示冲突，不自动顺延后续任务
- 删除都是软删除，可以恢复
- 提醒以「提醒时刻 + 提前量」计算：提醒时刻默认 09:30，可以在设置里改
- 筛选是叠加在当前范围上的：比如先点某个项目，再筛「进行中 + 高优先级」，就是那个项目里的子集
- 保存视图存的是筛选条件和视图，不存结果，所以任务变化后视图看到的是最新的数据
- 重复任务只在「从未完成变成完成」的那一刻生成下一次；反复取消再勾选不会生成多条
- 重复任务逾期很久才补上时，下一次会直接对齐到未来那一天，不会补出一串历史任务

## 提醒的两个真实限制

1. **网页通知只在页面打开时有效。** 浏览器不给你后台常驻的能力，页面关掉就不会弹。
   补偿措施：页面重新打开时，期间到点的提醒会补弹出来，不会静默丢掉。
2. 桌面通知需要 https 或 localhost，并且要你手动授权一次；没授权时应用内的提醒卡片照样会弹。

想做到「关掉也能收到手机通知」，需要推送通道和一台常开设备，这是设计方案里第 5 阶段以后的事。

## 数据设计（重要）

所有修改都写成一条**只追加的变更记录**，当前状态由日志重放得到（见 `src/data/log.ts`）。
这么做是为了以后能上多设备同步，三条规则不能破：

1. 主键用 UUID，不用自增整数（跨设备合并会撞车）
2. 删除是软删除，每条记录带 `updatedAt` / `deletedAt`
3. 同步的是变更日志，不是数据库文件本身

冲突按字段级"后改的赢"解决。第 2、3 条见 [设计方案.md](设计方案.md) 第 2 节。
